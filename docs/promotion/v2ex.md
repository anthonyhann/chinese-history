# V2EX 发帖文案（分享创造 / 程序员节点）

**标题**：我把中华上下五千年的帝王将相做成了一个开源数据库（JSON + SQLite，clone 即用）

**正文**：

各位 V 友好，分享一个自己闷头做了几天的项目。

**chinese-history**：中华历史人物·事件·文物开源结构化数据库
https://github.com/anthonyhann/chinese-history

灵感来自 chinese-poetry（53.8k star 的最全古诗词库）。古诗词有了，历史也该有一个——但历史数据比诗词难做得多：有生卒争议、有纪年换算、有出处考证。所以这个项目把「出处」做成了一等公民。

**目前的数据量（v1.4.0，全部可验证）**：

- 370 位历史人物：266 位帝王（秦始皇到溥仪，含十六国/十国/西夏/大理，帝系前 221 年贯通到 1912 年）+ 82 位名臣将相（商鞅、诸葛亮、李白、王安石、王阳明、林则徐……）
- 154 个重大事件：玄武门之变、澶渊之盟、安史之乱、靖康之变、崖山海战、鸦片战争、辛亥革命……每条带《史记》《汉书》卷次出处
- 551 个年号表：汉武帝「建元」（前 140）到宣统（1912），年号→公历映射
- 62 件文物：大都会、史密森尼亚洲艺术馆、克利夫兰的中华珍宝，**全部 CC0 图片可直接用**
- 94% 人物已对齐 Wikidata QID，可接全球知识图谱

**技术上几个点**：

```bash
git clone https://github.com/anthonyhann/chinese-history.git
python3 tools/validate.py   # 零依赖校验器：JSON Schema + 引用完整性 + 出处强制
python3 tools/build_sqlite.py  # 一键构建 SQLite（1.8MB 单文件全库）
```

- 数据全 JSON 分片存储，改数据 = 提 PR，CI 拦无出处的提交
- 时间双轨制：「秦始皇三十七年七月丙寅」原文 + 归一化公历（负数=公元前）+ disputed 学术争议多值并存
- 史实有争议的不删不改，多值各标出处（比如刘邦生年前 256 还是前 247）
- 打 tag 自动构建 SQLite + JSON 快照发 Release，不用网盘传数据
- 每条 AI 生成的数据在 `_meta` 里留了模型和 prompt 版本，可复现

**诚实声明**：数据由 AI 流水线生成 + 部分抽查，目前还没有任何一条经过逐条人工核验。`_meta` 记录了生成模型和 prompt 版本（可追溯，但不等于正确性保证），用前请自行核对 sources。另一个已知短板：`disputed[]` 争议多值目前只有 9 条，远没铺开。纠错 PR 必须带出处，无出处不合并。

文物图片许可是分层的：事实数据 CC0 随便用，描述文本 CC BY-SA，图片按馆方许可逐条标注（大都会/史密森尼/克利夫兰是 CC0 可直接用，大英博物馆禁商用只放链接）。

欢迎试用、捉虫、提 PR。想共建的可以先从「你家乡的博物馆里有哪些中华文物」开始，一条数据一个 PR。

**回帖预案**（常见问题的答复口径）：

- Q: 和 CBDB（中研院历代人物库）什么区别？A: CBDB 是学术级，对接学者；本项目对标开发者，JSON clone 即用，中文优先。学术深度请看 CBDB。
- Q: 数据靠谱吗？A: AI 生成 + 人工抽查 + 出处强制 + CI 校验 + Wikidata 交叉验证。每条都带出处，欢迎捉虫。
- Q: 为什么不爬百度百科？A: 版权。描述文本全部原创，事实数据无版权，文物图片按馆方许可逐条标注。
